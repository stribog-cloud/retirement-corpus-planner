# Export Pipeline

> Contributor contract for PDF, CSV, scenario JSON, tax-law JSON, and Adviser / CA Pack output.

## 0. TL;DR

Exports must speak the same live model state as the dashboard. A stale export is a product defect. Every export must include caveats, provenance, and enough evidence for review.

## 1. Export Types

| Export | Purpose | Required Evidence |
|--------|---------|-------------------|
| PDF | Planning narrative | KPIs, charts, caveats, tax provenance, assumptions fingerprint, advisor actions |
| CSV | Ledger audit | Metadata, assumptions, tax-law info, risk method, annual and monthly rows |
| Scenario JSON | Scenario portability | Snapshot assumptions, output summary, notes, source, fingerprint |
| Tax-law JSON | Tax review | Active ruleset export and draft ruleset export, source, version, update date, product and slab rules |
| Adviser / CA Pack JSON | Professional review | Caveats, assumptions, tax-law JSON, scenario comparison, saved scenarios, risk summary, CSV text |

## 2. Live-state Rule

Export handlers must use the same normalized state, calculation result, tax-law object, scenario history, and risk metadata shown in the UI. Do not cache export-only model results unless the cache is invalidated by every relevant state change.

## 3. Single-file Artifact Rule

`index.html`, `Retirement Corpus & Income Planner.html`, and `dist/*.html` are generated by `npm run build`. Source changes must be made in `src/`, `app.html`, tests, scripts, or docs, then rebuilt.

## 4. Privacy Rule

Every export path must treat output as sensitive. Keep caveats and local-data language in sync with Trust Center and Help.

## 5. Testing Rule

Export changes require E2E smoke for PDF, CSV, scenario JSON, active and draft tax-law JSON, and review-pack JSON. They also require at least one assertion that the exported metadata reflects the live changed state. Tax-law JSON coverage must prove the active export matches the applied model ruleset and the draft export preserves the editor draft without silently applying it.

## 6. Known Limitation

The PDF is not currently claimed as PDF/UA accessible. Keep that limitation visible in user docs until an accessibility-grade PDF pipeline exists.
